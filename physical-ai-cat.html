松尾研「Physical AI 応用編1」

03

「察して」を、数値にする。

自由な日本語を、3つの行き先へ。学習済みの多言語Sentence Transformerで文の近さを比較し、ROS 2を通じて猫に移動を頼む。

01 / INPUT

お願いを分ける

「それから」「最後に」などで区切り、順序を取り出す。

02 / AI INFERENCE

意味の近さを比べる

入力と例文をベクトル化。コサイン類似度から行き先を選ぶ。

03 / PLAN

行き先を並べる

ごはん・窓辺・寝床の座標へ変換し、移動計画を保存。

04 / CONTROL

走って、止まる

位置情報を受け取り、進む向きと速度を調整。到着したら停止。

言い換えても、行き先は通じた。

実行ログ抜粋 / 移動開始から完了まで約39秒

AIは学習済みモデルの推論を使用。追加学習はしていません。文章の分割と移動制御はルールベースです。対応先は3か所で、複雑な否定表現や障害物回避、四足歩行には対応していません。猫の外観を持つ車輪ロボットです。

WSL / Ubuntu 22.04ROS 2 HumbleGazebo FortressPython 3.10MiniLM-L12-v2 / CPU
04

華麗なデモの、地味な裏側。

未来のロボットを動かす前に、今日のターミナルを見分ける必要があった。

LOG 01AI以前に、パッケージが見つからない。

WSL上のUbuntuを準備。ROSの配布元が登録されておらずインストールで停止したため、ROS 2のAPTソースを追加し、HumbleとGazeboの環境を整えた。知能より先に、住所録が必要だった。

LOG 02ロボットがいない。存在論は後回し。

world.sdfの場所とモデルの参照先を確認。リソースパスを設定し、GazeboでdemoRobotを探して視点を合わせた。猫になる前のロボットを、まず画面内に取り戻した。

LOG 03猫より先に、画面が踊りだした。

3D表示の点滅に対処。最終的にCPUによるソフトウェア描画とOgre2の組み合わせで安定した。LIBGL_ALWAYS_SOFTWARE=1 と --render-engine ogre2 を起動スクリプトにまとめ、再起動後も使える形にした。

LOG 04車輪に耳を付けたら、愛着が湧いた。

元の移動ロボットの物理構造を活かし、耳・顔・しっぽを追加。ごはん、窓辺、寝床にも目印を置いた。日本語判定と移動制御を接続し、お願いの言い換えと訪問順の変更を実際に確かめた。

LOG 0552秒の傑作、尺不足で撮り直し。

提出用動画を1分6秒で再撮影。コード、モデル、依存関係、READMEをGitHubにまとめ、PDFレポートと動画を用意して課題提出まで完了。動いた瞬間と、提出できた瞬間は、別の達成感だった。
